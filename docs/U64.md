Installing Habitat on the Ultimate 64
=====================================

This guide walks through getting the Habitat client running on an Ultimate 64
(or a stock C64 paired with an Ultimate II/II+ cartridge), connected to a
Neohabitat server over your home network.

It assumes you already have:

- An Ultimate 64 with firmware **3.11 or later** (any revision: Mark I, II,
  Elite, Elite-II).
- The U64 on your local network (Ethernet, or WiFi if you have an Elite-II).
- Either a working HDMI display or a composite/S-Video monitor.
- A Neohabitat server reachable from your U64. The public community server
  at `neohabitat.demo.spi.ne:1701` is the default; you can also run your own
  from <https://github.com/frandallfarmer/neohabitat>.

The whole process takes about ten minutes. If anything looks unfamiliar,
jump to [Troubleshooting](#troubleshooting) at the bottom.

What you're installing
----------------------

The release zip contains three files:

| File              | What it is                                                                            |
|-------------------|---------------------------------------------------------------------------------------|
| `Habitat.crt`     | The EasyFlash cartridge image. Contains launcher, game engine, and all disk-B data.   |
| `habitat-u64.cfg` | A U64 configuration snippet that wires up the SwiftLink/ACIA modem at `$DF80`.        |
| `README.txt`      | A short standalone version of this guide (handy if you copy the folder somewhere).    |

You only need the `.crt` and `.cfg` files on the U64 itself.

---

Get the release
---------------

Either download a pre-built release, or build one from source.

### Pre-built (recommended)

1. Open <https://github.com/ssalevan/habiclient/releases>.
2. Download the most recent `Habitat-U64.zip`.
3. Unzip it locally. You should see a folder called `Habitat-U64/` containing
   the three files above.

### Build from source

```bash
git clone https://github.com/ssalevan/habiclient.git
cd habiclient
./dockercart
```

`./dockercart` builds a Rocky Linux 9 x86_64 container (via QEMU on Apple
Silicon) and runs the full pipeline: macross assembles the engine, slinky
links it, cc65 compiles the launcher, `build_crt.py` packs everything into
an EasyFlash CRT, and the build closes by zipping up `Dist/Habitat-U64/` as
`Dist/Habitat-U64.zip`.

The full build takes 2–4 minutes on a fast laptop, longer on Apple Silicon
because the container runs under QEMU.

Copy files to the U64
---------------------

You have three options, in order of "least to most networky":

### Option 1 — USB stick (simplest)

1. Insert a FAT32-formatted USB stick into your laptop.
2. Copy the entire `Habitat-U64/` folder onto the stick. A path like
   `USB1/HABITAT/` is conventional, but any folder works.
3. Plug the stick into the U64's front USB port.

### Option 2 — FTP

The U64 runs an FTP server on port 21 when network services are enabled.

```bash
ftp -p ftp://<u64-ip>/
# password: blank (just press return)
# put the files into /USB1/HABITAT/
```

The repo includes `u64_deploy.py` which automates this for the disk-image
build path. For the cartridge build you can copy `Habitat.crt` and
`habitat-u64.cfg` manually with any FTP client.

### Option 3 — REST API push (no USB stick needed)

If you only want to run the cartridge *right now* (without saving it to USB)
the U64's HTTP REST API can boot a CRT image directly:

```bash
./upload_u64.sh 192.168.1.158 Dist/Habitat.crt
```

This POSTs the CRT to `http://<u64-ip>/v1/runners:run_crt`. The U64 resets
and boots straight into Habitat. **You still need to have loaded
`habitat-u64.cfg` at least once** so the modem settings are in place — see
the next section.

Load the modem configuration
----------------------------

The U64 ships with the modem emulator **disabled** by default. The provided
`habitat-u64.cfg` flips on a 6551-compatible ACIA at `$DF80` with NMI
interrupts, which is exactly what Habitat's serial driver expects.

You only need to do this **once**, then save the config to flash.

1. From the U64 menu (press <kbd>F1</kbd> or briefly press the menu button on
   the back of the unit) navigate to your USB stick.
2. Highlight `habitat-u64.cfg` and press <kbd>RETURN</kbd>.
3. Select **"Load into current config"**. You should see
   *Loading configuration successful!*
4. Press <kbd>RETURN</kbd> to dismiss.
5. Press <kbd>F2</kbd> to open the U64 setup screen.
6. Scroll down to **Configuration** and press <kbd>RETURN</kbd>.
7. Choose **Save to Flash** and confirm.

If you skip the *Save to Flash* step the modem settings will be lost on the
next power cycle, and the game will hang at the connect screen until you
reload the config.

### What the `.cfg` actually changes

```ini
[U64 Specific Settings]
System Mode=NTSC

[C64 and Cartridge Settings]
Bus Sharing - I/O1=Both
Bus Sharing - I/O2=Both
Bus Sharing - Interrupts=Both
Command Interface=Enabled

[Network Settings]
FTP File Service=Enabled
Web Remote Control Service=Enabled

[Modem Settings]
Modem Interface=ACIA / SwiftLink
ACIA (6551) Mapping=DF80/NMI
Listening Port=3000
Drop connection on DTR low=Disabled
CTS Behavior=Active (Low)
DCD Behavior=Active when connected
DSR Behavior=Active when connected
Set Socket Opt TCP_NODELAY=Enabled
```

The key lines are:

- **`Modem Interface=ACIA / SwiftLink`** — exposes the 6551 ACIA to the C64.
- **`ACIA (6551) Mapping=DF80/NMI`** — maps the four ACIA registers to
  `$DF80–$DF83` and wires `IRQ` to the NMI line. The game's RS-232 driver
  receives bytes via an NMI handler.
- **`Drop connection on DTR low=Disabled`** — without this the U64 hangs up
  every time the C64 reset toggles DTR.
- **`Set Socket Opt TCP_NODELAY=Enabled`** — disables Nagle's algorithm so
  small packets aren't buffered for 40ms, which would otherwise make the
  game feel sluggish.

The PAL/NTSC line is informational — Habitat will run on either, but the
original was an NTSC game and the raster timing is calibrated for it.

> **HDMI users:** the `.cfg` deliberately does **not** touch video settings,
> so loading it cannot black out your screen. If video does disappear, you
> probably hit *Factory Reset* by accident; reconnect over composite and
> re-enable HDMI from **F2 → U64 Specific Settings**.

Run the cartridge
-----------------

1. Press <kbd>F1</kbd> to open the menu.
2. Navigate back to your USB stick (e.g. `/USB1/HABITAT/`).
3. Highlight `Habitat.crt` and press <kbd>RETURN</kbd>.
4. Choose **"Run Cartridge"**.

The screen blanks for ~1 second, then the launcher splash appears.

---

Playing
-------

1. **Name field.** Type a character name, up to 12 characters. The launcher
   accepts standard lowercase keyboard input (the C64 displays uppercase on
   screen, but the keyboard sends lowercase PETSCII).
2. Press <kbd>RETURN</kbd> to move to the **server connection** field.
3. Press <kbd>RETURN</kbd> again to dial the default Neohabitat server.

You'll see the launcher send `ATDT...` modem commands, the U64 reports
`CONNECT 1200`, and a moment later the game cuts to the Habitat title screen
and your avatar drops into the first region.

In-game controls are the original Habitat ones:

- **Joystick (port 2)** — primary input. Move the pointer, click to walk,
  click on objects to interact.
- **Function keys** — `F1` GET, `F3` DO, `F5` PUT, `F7` TALK.
- **<kbd>RUN/STOP</kbd>** during region transitions cancels the move.

Configuring the server address
------------------------------

The launcher defaults to dialing the community Neohabitat server. If you're
running your own server (or testing against a development branch) you have
two options:

### Edit before building

`Launcher/launcher.c` contains the dial-string constants near the top. Edit
the host/port literals, rebuild with `./dockercart`, and ship the new CRT.

### Configure on the U64 side

The U64 modem emulation accepts a *map* of outbound destinations, set via
its config. Open **F2 → Modem Settings → Outgoing Connections** and add a
mapping like:

```
Dial string: 1234
Maps to:     your-server.example.com:1701
```

Then in the launcher, type `1234` when prompted for the server — the U64
will translate the dial string to the real TCP destination.

Deploying from your laptop (advanced)
-------------------------------------

For iterative development the included helper scripts cut the build/test
loop down to a single command.

```bash
# Build a fresh CRT, push it to the U64, and reboot into it
export U64_IP=192.168.1.158
./dockercart && ./upload_u64.sh
```

For testing the classic disk-image build:

```bash
# Upload Habitat-A.d64 / Habitat-B.d64 to /USB1/HABITAT/ and auto-run
python3 u64_deploy.py --mount --run
```

The Python tooling (`u64_tool.py`) also exposes a programmatic interface:
peek/poke RAM, capture screenshots, inject keystrokes, reset. The
`u64_debug.py` and `grab_debug_stream.py` scripts are dev-loop helpers used
during the SwiftLink driver bring-up; they're documented inline.

Legacy builds
-------------

The original disk-image build path still works for stock Commodore 64
hardware:

- **`Habitat-A.d64`** — boot disk: launcher, splash screen, login.
- **`Habitat-B.d64`** — data disk: behaviors, images, sounds. The game asks
  for this disk after login.

Build them with `./dockerbuild` (instead of `./dockercart`). Load `Habitat-A`
in any 1541-compatible drive (1541, 1571, 1581, SD2IEC, Pi1541, Ultimate II,
or the U64's own disk emulation), `load"*",8,1` from BASIC, and follow the
prompts.

On the launcher's modem-selection screen, press <kbd>M</kbd> to toggle
between:

- **SwiftLink** — uses the ACIA at `$DE00` (real SwiftLink/Turbo232
  cartridge, or U64 emulated modem mapped to `$DE00`).
- **User Port** — uses KERNAL RS-232 at 1200 baud, bit-banged via CIA2.
  Requires a real RS-232 user-port adapter and a null-modem to your server
  bridge.

The cartridge build uses the SwiftLink path exclusively (mapped to `$DF80`),
since that's the only mode the EasyFlash boot sequence supports.

Troubleshooting
---------------

### The launcher draws, but `ATDT...` never completes — "Lost Carrier"

The U64 isn't routing modem traffic. Three things to check, in order:

1. **Modem config is loaded.** Open **F2 → Modem Settings** and confirm
   *Modem Interface* says `ACIA / SwiftLink` and *Mapping* says `DF80/NMI`.
   If they don't, reload `habitat-u64.cfg` and *Save to Flash*.
2. **Network is up.** The U64 menu has a network status line — make sure
   you have an IP. The Elite-II's WiFi sometimes needs a manual reconnect
   after a long sleep.
3. **DNS resolves the server.** If you're using a hostname rather than an
   IP, the U64 needs DNS. The factory default DHCP setup handles this; if
   you set a static IP, double-check the DNS server entry.

### Black screen after loading `.cfg`

The `.cfg` doesn't change video settings, so this almost always means you
hit *Factory Reset* (which lives near the *Load Config* option in some
firmware versions). Connect a composite cable, press <kbd>F2</kbd>, and
re-enable HDMI under **U64 Specific Settings**.

### Cartridge boots, but characters draw as garbage

This is the classic CIA timer / raster sync issue from the original 1986
client. It almost never happens on the U64 (the FPGA timings are spot-on),
but if it does:

- Make sure *System Mode* in the U64 settings matches the actual region of
  your display (NTSC for the original game; PAL works but adjusts raster
  timing).
- Power-cycle the U64 fully. A warm reset can leave CIA1 in an
  intermediate state; cold boot fixes it.

### Game freezes when crossing into a new region

The cartridge build streams behaviors and images out of cart flash via an
in-RAM disk shim. Region transitions briefly disable interrupts; on a
heavily-loaded U64 (multiple cartridges chained, debugging tools attached)
this can timeout. Disconnect any non-essential cartridges and retry.

### "Insert Disk B" prompt appears on the cartridge build

This indicates the disk-B shim didn't initialise. It's almost always caused
by:

- An older `Habitat.crt` (pre-cartridge support) — re-download from
  Releases.
- The U64 firmware being older than 3.11 — upgrade.

### REST upload returns HTTP 403 / 500

The U64's REST endpoints are off by default on some firmware versions.
Re-load `habitat-u64.cfg` to turn on *Web Remote Control Service*, save to
flash, and retry. If the upload still fails, check the firewall on your
local network — some routers block outbound port 80 to unknown devices.

### `./dockercart` fails on Apple Silicon

The build runs under QEMU x86_64 emulation. Make sure Docker Desktop's
*"Use Rosetta for x86/amd64 emulation"* setting is **enabled** (Settings →
General). Without Rosetta the QEMU layer is much slower and occasionally
trips an assertion in `slinky`.

How it works
------------

This section is for the curious — you don't need to read it to play.

The Ultimate 64 build differs from the original 1986 client in three ways:

1. **Networking via emulated SwiftLink.** The original used a 1200-baud
   modem (or rarely a SwiftLink cartridge) plugged into the user port or
   expansion port. The U64 firmware exposes a 6551 ACIA at `$DF80` whose
   transmit byte is forwarded to a TCP socket and whose receive byte is
   delivered from one. The game's serial driver (`Main/rs232.m`) was
   updated to drive the ACIA via an NMI receive handler.

2. **EasyFlash cartridge format.** `build_crt.py` packs `habitat.prg`
   (launcher + decompressed engine), `mcmg.prg` (uncompressed game), and
   `Habitat-B.d64`'s contents into 8 KB banks of an EasyFlash 1 cartridge.
   On boot, the cartridge starts in Ultimax mode, copies a small loader to
   page 1, transitions to 8 K cart mode, and streams the launcher + engine
   into RAM. No Exomizer decompression — banks copy verbatim, so startup is
   essentially instant.

3. **In-RAM disk-driver shim.** The original game streams behaviors and
   images from Disk B during gameplay (e.g. when entering a new region).
   On the cartridge build, `loader.m` installs a tiny shim that intercepts
   the disk driver's read entrypoint and serves data from cart banks
   instead of the IEC bus. From the game's perspective nothing has changed.

For the gory details — Macross assembly conventions, the slinky linker's
segment placement, the cc65 IRQ patches, the WDC 65C51 TDRE bug, and the
QLink sequence-collision fix — see [CLAUDE.md](../CLAUDE.md).
